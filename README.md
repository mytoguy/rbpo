# Parking Management System
## Предметная модель (Сущности)
*   **User** — владелец автомобиля.
*   **Vehicle** — автомобиль, привязанный к пользователю (Один-ко-Многим).
*   **ParkingZone** — парковочная зона с ограниченной вместимостью (`capacity`) и почасовой ставкой (`hourlyRate`).
*   **ParkingSession** — сессия парковки (въезд/выезд) конкретного автомобиля в конкретной зоне.
*   **ParkingPass** — абонемент на парковку для автомобиля в определенной зоне на заданный период дат.

## Реализованные бизнес-возможности
В системе реализованы 5 законченных бизнес-операций (помимо стандартного CRUD):
1.  **Начало парковки (`POST /api/parking-sessions`)** — проверяет, что автомобиль еще не припаркован (нет открытых сессий) и что в зоне есть свободные места (количество активных сессий меньше `capacity`).
2.  **Завершение парковки (`PATCH /api/parking-sessions/{id}`)** — рассчитывает стоимость на основе времени стоянки и тарифа зоны. Если у автомобиля есть действующий абонемент на эту зону, стоимость обнуляется (`0`).
3.  **Покупка абонемента (`POST /api/parking-passes`)** — проверяет, что даты нового абонемента не пересекаются с уже существующими абонементами для данного авто и зоны.
4.  **Удаление парковочной зоны (`DELETE /api/parking-zones/{id}`)** — запрещено, если на зоне есть активные парковочные сессии или действующие абонементы.
5.  **Передача автомобиля (`PATCH /api/vehicles/{id}/transfer`)** — меняет владельца авто. Запрещено, если автомобиль в данный момент находится на парковке (есть незакрытая сессия).
